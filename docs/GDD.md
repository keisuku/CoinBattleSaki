## 0. コンセプト

### ワンライナー
リアルタイムの仮想通貨先物市場データでBotキャラが戦う、
ファンタジースポーツ × パチンコ演出のBot起用バトルゲーム。
Claude Codeで開発された最強Botは、本物の市場で勝てるのか？

### プロダクトの正体
- **ファンタジースポーツ**: ユーザーはBot（選手）を時間帯ごとに起用し、成績で競う
- **ウマ娘**: ニッチな世界（先物市場）をキャラで一般層に届ける
- **パチンコ**: 信頼度段階エスカレーション演出でリアルタイムの値動きを表現
- **リアルデータ**: ゲーム内の全てが本物の市場データで駆動される

### 他サービスとの根本的な違い
- **他（3Commas, Bybit等）**: トレードが前提のツール
- **CoinBattleSaki**: Bot起用判断で競う**ゲーム**。トレード不要

### コア価値
「ゲーム好きだけど暗号資産に触らない人が、ノーリスクで"いかがわしいマネーゲームの世界"を覗き見できるエンターテイメント」
- いかがわしい世界 = 怖いもの見たさの好奇心がフック
- ノーリスク = 自分のお金は1円も動かない
- 暗黙の価値 = 「この通知パターンに慣れたら、本当に先物やる時にも勝てそう」

### メタストーリー
「Claude Codeで最強Botは作れるのか？」
- 開発過程自体がIPの一部
- アプリ内で「CC製」を明示
- SNSで開発過程も配信（アプリへの導線にもなる）

## 2. 世界観

### トーン: ダーク × アンダーグラウンド × 超王道バトル
- SF2初期の「全ジャンル全世界の無差別バトル」の雰囲気
- いかがわしいアンダーグラウンドの世界だが、ねっとりせず爽快
- 清算されても立ち直る。遺恨を残さない

### 環境 = 市場状況
- 雇用統計前後 = 暴風雨の中の戦い
- 平常時 = 公園での穏やかな戦い
- 清算カスケード = 地震/火山噴火
- レンジ相場 = 霧の中の静けさ

### キャラクターの原型
**先物市場の実際の参加者をバトルキャラに翻訳する**:
- ヘッジファンド、オイルマネー、個人投資家、国家権力、取引所

SF2は「世界中の格闘技の頂点」を8キャラに圧縮した。
CoinBattleSakiは「先物市場の参加者の頂点」を8キャラに圧縮する。

> ⚠️ **キャラデザインの翻訳の媒介（何を通じて投資家をバトルキャラにするか）は
> このプロジェクト全体の骨格であり、最後に決める最重要事項。**

### キャラデザインの原則（SF2から抽出）
- シルエットだけで誰かわかる
- 色で即座に識別できる
- 戦い方が見た目に直結している
- 全員が全く違う方向性だが、一貫性がある
- 生成AIガチャでは到達不能。深い世界観 → デザイン力 → 画力 → 一貫性の順

## 3. ゲームループ

### ユーザー体験の全体フロー
```
1. Botキャラを知る（見た目 + 戦略特性）
2. 📱プッシュ通知「バトル始まった！！」（突然のエンカウント）
3. スマホを開く（背徳感）
4. 「今のBotでいいか？切り替えるか？ノーポジにするか？」（瞬間判断）
5. パチンコ的演出で推しBotの戦いを観戦（推しBot固定視点）
    → 信頼度段階エスカレーション
    → 尻すぼみ or 大爆発（必殺技/Bot対Botバトル/KO）
6. 成績が累積 → ランキングで他ユーザーと競争
7. SNSでアプリ画面を撮影して投稿（バイラル）
8. 日常に戻る → 1に戻る
```

### キラーフィーチャー: プッシュ通知 = 突然のエンカウント
- Botがポジションを取った瞬間に通知
- 市場は24時間365日 → 通知が来るタイミングが予測不能 → 中毒性と背徳感
- 通知が来たら即座にBot起用判断が求められる
- 実装: ローカル通知（バックグラウンドでBinance API監視 → サーバー不要）

### Bot起用判断
- リアルタイムでいつでも「ノーポジ / BotA / BotB / BotC...」を切り替え可能
- 「雇用統計前だからノーポジにしよう」「今のボラティリティならスキャルBotだ」
- この判断力がランキング上位への鍵

### ランキング
- ユーザー同士の成績ランキング（日次/週次/月次）
- 基盤: GameCenter (Apple) / Google Play Games（サーバー不要）
- ランキング対象 = 「稼いだ額」（元手は関係ない）

### 仮想資金
- 毎日10万円（仮想通貨）のお小遣いが配布される
- ランキング = その日/週/月に稼いだ額（元手は関係ない）

- 無料でも翌日自動復活
- ¥100 = 即復活の時短課金

## 5. 演出方式: パチンコ的信頼度エスカレーション

### なぜパチンコ的演出か
- 先物市場の「フェイクアウト（騙し）vs 本物のブレイクアウト」に完全一致
- 95%の退屈な時間問題を解決（小さな動きでも「来るか？来ないか？」で緊張感）
- パッシブ観戦と完全に合致（パチンコも「見てる」のが主体）
- 「激アツ演出が出た！」をスクリーンレコーディングしてSNS投稿するバイラル構造

### パチンコとCoinBattleSakiの決定的な違い

| | パチンコ | CoinBattleSaki |
|---|---|---|
| 結果の決定タイミング | 演出の前に確定済み | 演出と同時進行（市場はリアルタイム） |
| 演出の役割 | 結果を「伝える」エンタメ | 展開を「予感させる」リアルタイム実況 |
| 信頼度の意味 | 統計的な当たり確率 | Bot/市場状況からの勝率推定 |
| ダマシの構造 | プログラムが意図的に演出 | 市場そのものがダマシを生む |
| ラッシュ中の損失 | なし（減らない） | あり（減ることもある） |

### 信頼度モデル: TP/SL軸

Botには必ず利確(TP)と損切り(SL)が存在する。これが信頼度の軸になる。

```
信頼度 = 価格のTP/SL間での正規化位置 + 市場の勢い補正

SL ←────────────────────────→ TP
0%              50%              100%
 (苦戦)        (拮抗)          (攻勢)

基本信頼度 = (現在価格 - SL) / (TP - SL) × 100
```

### Phaseフロー（通常モード）

```
Phase 0: 静寂
  │ 市場は動いているが、Botの注目シグナルに変化なし
  │ 画面: チャートの具現化（穏やかな背景）
  │
  ▼ シグナル1個点灯
Phase 1: 予兆
  │ 「…ん？」BGM微変化、Botが何かに気づいた表現
  │
  ├─→ シグナル消失 → Phase 0に戻る（ハズレ変動）
  │
  ▼ シグナル2個点灯
Phase 2: 緊張
  │ 「来るか…？」画面の色味変化、Botが構える
  │
  ├─→ シグナル減少 → Phase 1 or 0に戻る（ハズレ変動）
  │
  ▼ シグナル3個（条件成立）→ エントリー！
Phase 3: 戦闘開始
  │ 派手な突入演出、TP/SLラインが可視化
  │ 信頼度: 50%（エントリー直後 = TP/SL中間地点）
  │
  ▼ 価格が動く
Phase 4: 戦闘中（TP/SL間の攻防）
  │ TPに接近 → 信頼度UP、攻勢演出
  │ SLに接近 → 信頼度DOWN、苦戦演出
  │ SL付近から反転 → 復活演出（「…まだだ！」）
  │ TP付近から反転 → 逆転演出（「まさか…」）
  │
  ▼ TP到達 or SL到達 or Bot決済判断
Phase 5: 決着
  │ 勝利: TP到達 → 勝利演出（幅に応じてノーマル勝利〜大勝利）
  │ 敗北: SL到達 → 敗北演出
  │ Bot判断: 途中決済 → 含み益なら勝利、含み損なら敗北
  │
  ├─→ 勝利 → Phase R（ラッシュモード）に遷移
  └─→ 敗北 → Phase 0に戻る
```

### シグナル重なり = パチンコの疑似連

各Botは複数のシグナル条件を持つ。重なるほどエントリーに近づく:

| パチンコ | CoinBattleSaki |
|---|---|
| 変動開始（ハズレ通常） | シグナル0個（静寂） |
| 疑似連1回 | シグナル1個（予兆） |
| 疑似連2回 | シグナル2個（緊張） |
| 疑似連3回→リーチ成立 | シグナル3個→エントリー |

各Botが同じチャートを違う目で見ている:
```
同じBTC/USDTチャート上で:
  JOHN（5分足トレンドフォロー）→ 「追い風が吹いてきた…」
  MIKE（5分足逆張り）        → 「ここで反転だ…！」
  ALEX（1時間足トレンド）     → 「まだ様子見だな…」
```

### ラッシュモード（Phase R）

Phase 5で勝利した場合、ラッシュモードに突入する。
パチンコの「確変/ラッシュ」に対応するが、**お金が減ることもある**のが最大の違い。

```
【ラッシュ中のPhase遷移】
Phase R-0: 次のシグナル探索（高速、Phase 0-1をスキップ/超高速通過）
Phase R-2: 再エントリー
Phase R-3〜R-4: 戦闘中
Phase R-5: 決着
  → 勝利: コンボ継続（コンボN+1）
  → 敗北: 撤退判定
    → 撤退条件未到達: ラッシュ継続（コンボリセット）
    → 撤退条件到達: ラッシュ終了 → Phase 0に戻る

【ラッシュの撤退条件（Bot内蔵）】
1. 最高利確ライン到達 → 「完全勝利！」演出
2. シグナル弱体化 → 「戦略的撤退！」演出
3. 連続敗北（N連敗） → 「流れが変わった…」演出
4. 累積損益マイナス転落 → 「…撤退。」演出
5. タイムアウト（シグナル枯渇） → 「波が去った」演出

【ユーザー事前設定（デプロイ時に選択）】
├── 堅実型: 利確ライン低め、シグナル弱化で即撤退
├── 標準型: バランス（デフォルト）
└── 攻撃型: 利確ライン高め、多少のシグナル弱化は無視
→ Botパラメータとして処理。管理工数はユーザー数に比例しない。
```

### ラッシュの重なり = 最高潮

```
通常: 1体だけラッシュ中       → 楽しい
稀:   2体同時ラッシュ         → かなり興奮
激レア: 3体以上同時ラッシュ    → 「祭り」状態
→ パチンコの「確変連チャン」に相当
→ 「あの日3体同時ラッシュ来たんだよ」と語りたくなるSNS映え体験
```

### 時間足と演出テンポ

Botの時間足が演出のジャンル（テンポ）を決める:

| 時間足 | ドラマの型 | 1エピソードの長さ | 1日の回数 |
|---|---|---|---|
| 5分足 | 短編アニメ連続視聴 | 約6分 | 数十回 |
| 15分足 | 30分アニメ | 約30分 | 数話 |
| 1時間足 | 映画 | 2-4時間 | 0-1本 |

```
推奨ポートフォリオ構成（常時エンタメ設計）:
├── 5分足Bot × 2-3体 → 常にどれかが動いている（常時エンタメの基盤）
├── 15分足Bot × 2-3体 → たまに大きなラッシュが来る（中期のドラマ）
└── 1時間足Bot × 1-2体 → 超レアな「スーパーラッシュ」（記憶に残る体験）
→ いつ画面を見ても「何かが動いている」状態
```

### キャラ特性とTP/SL幅の対応

| キャラ特性 | 取引パラメータ | 演出的な意味 |
|---|---|---|
| 大勝ち狙い型 | TP幅が広い | 長期戦。なかなか決着がつかない = 長いリーチ |
| 堅実型 | TP幅が狭い | 短期決着。テンポが良い = ノーマルリーチ |
| 体力がある | SL幅が広い | 追い込まれても耐える = 復活演出が多い |
| すぐ死ぬ | SL幅が狭い | 一瞬で負ける可能性 = 瞬殺演出あり |
| 一発逆転型 | TP遠い×SL近い | 負けやすいが勝つとデカい = 激アツキャラ |
| 安定型 | SL遠い×TP近い | 勝ちやすいが地味 = 安定キャラ |

### SNSバイラルの仕組み
- ユーザーが自発的にアプリ画面を撮影してSNS投稿
- 「アプリの画面自体が撮りたくなるほど面白い」必要がある
- パチンコの激アツ演出をスマホで撮る行動と同じ構造
- 「3体同時ラッシュ」「SL寸前からの復活勝利」が最もバイラルする瞬間

## 6. キャラクター（Bot）設計

### 設計原則
SF2のキャラデザが30年色褪せない理由:
1. 全世界の格闘技の頂点を、1キャラに圧縮した
2. 深い世界観が先にあって、デザインが生まれた（デザインが先ではない）
3. 8体全部が全く違う方向性なのに、同じ画面に並んでも違和感がない一貫性

### Botの戦い方 = キャラの個性
- スキャルピング型 = 手数が多いが浅い攻撃（百裂脚的）
- スーパーロング型 = 一撃が重いが遅い（ザンギエフ的）
- グリッド型 = 面制圧（ダルシム的リーチ）
- デルタニュートラル型 = 影に潜む（バルログ的）

### Bot進化システム
- 負けたBotは修行して新バージョンとして帰ってくる
- マザーBotから門下生が出てくる（リュウ→ケン→豪鬼の構造）
- Botの改良は開発者がClaude Codeで実際に行い、その過程もコンテンツとして公開

### 課金とBotの関係
- **全Botアクセス無料**（Pay to Winなし）
- 課金はスキン/見た目の変更のみ

## 8. マネタイズ

> 詳細は ADR-0004 を参照

### プラットフォーム: App Store / Google Play

### 課金モデル: 完全無料DL + 通知課金 + スキン課金

| 項目 | 価格 | 内容 |
|------|------|------|
| アプリDL | 無料 | 全Bot・全機能アクセス可 |
| プッシュ通知（無料枠） | ¥0 | 1日5回まで |
| プッシュ通知（有料） | ¥1,000/月（将来¥3,000） | 1日30回 |
| 即復活（全損時） | ¥100 | 仮想資金10万円に即復活 |
| キャラスキン | 個別価格 | 見た目のみ変更、性能差なし |

### 通知課金の価値
- 通知なし = アプリを開いて待つだけの時間が長すぎて実質プレイ不能
- 通知あり = 日常生活の中で突然エンカウント（ゲームとして成立）
- ランキング上位勢は全員課金（判断機会が多い = 有利）
- 将来的には「この通知に慣れておけば先物で勝てそう」という深層動機

### 絶対にやらないこと
- ❌ ゲーム内通貨の換金
- ❌ ガチャ
- ❌ 実際の暗号資産を賭けるシステム
- ❌ 投資助言・投資シグナルの提供
- ❌ コピートレード機能
- ❌ 投資成績による成功報酬
