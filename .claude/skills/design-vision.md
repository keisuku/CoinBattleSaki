# デザインビジョン管理 Skill

## Description
WEBデザイン・キャラクターデザイン・全体のトーン&マナーを統括する。
見た目のデザインだけでなく「この体験は何が面白いのか」「ユーザーにどんな感情を届けるか」
という体験設計レベルからの一貫性を守る。

## 自動トリガー条件
- UI/UXに関する提案・実装時
- キャラクターの設定・ビジュアル議論時
- 新機能が「ユーザー体験」に影響を与える時
- 演出・アニメーション・エフェクトの議論時
- マーケティング・SNS展開の議論時

## Instructions

### 1. コアエモーション設計（最上位の意思決定）

> **未決定**。以下の候補からPhase 0で決定する。
> 決定するまでは、全ての提案においてこの問いを意識する。

#### 「このアプリを体験した人に、最も持って帰ってほしい感情は？」

| エモーション | 体験の特徴 | 参考事例 | 設計方針 |
|-------------|-----------|---------|---------|
| 興奮・スペクタクル | 「うわ、すげえ！」 | カイジ, 格ゲー大会 | 演出過多OK、正確性は二の次 |
| 知的好奇心・学び | 「なるほど！」 | TradingView, 3Blue1Brown | 情報量多め、演出は補助 |
| 愛着・推し活 | 「このキャラ推す！」 | ウマ娘, FGO | キャラの個性が最優先、戦略は背景 |
| 創造欲・参加欲 | 「自分もやりたい！」 | Minecraft, QuantConnect | ユーザー参加型、カスタマイズ性 |
| 習慣・日課化 | 「今日の結果は？」 | ソシャゲログイン, 株価チェック | 定時更新、通知設計が重要 |

→ **これが決まらないと、全てのデザイン判断が宙に浮く。Phase 0の最優先タスク。**

### 2. トーン&マナー管理

#### トーンの軸（未決定。以下から選ぶ or 組み合わせる）

##### 世界観の温度
- **ホット（熱血）**: カイジ的。「ここで張らなきゃ男じゃない！」
- **クール（知的）**: 攻殻機動隊的。「最適解を計算する」
- **ポップ（楽しい）**: ウマ娘的。「みんなで応援しよう！」
- **シュール（ネタ）**: ポプテピピック的。「なんかよくわからんけどウケる」

##### 情報レベル
- **ガチ**: RSI, MACD, ファンディングレートを画面に表示。トレーダー向け
- **ライト**: 「強気」「弱気」「様子見」程度の表示。一般向け
- **ゼロ知識**: トレーディング要素を完全に隠す。キャラバトルとしてのみ見せる

##### ビジュアルスタイル候補
- **ドット絵（SF2風）**: ノスタルジック、インディーゲーム感
- **アニメ調（ウマ娘風）**: IP展開しやすい、制作コスト高
- **ミニマル（figma/linear風）**: 洗練された印象、制作コスト低
- **サイバーパンク**: 仮想通貨との親和性高、ダークなトーン
- **AI生成ベース**: コスト最低だが一貫性の維持が課題

### 3. デザイン提案時のチェックリスト

#### 体験一貫性チェック
- [ ] コアエモーションと矛盾しないか？
- [ ] トーンが他の画面/機能と統一されているか？
- [ ] 情報レベルがターゲットユーザーに合っているか？
- [ ] 初見のユーザーが5秒で「何をしているアプリか」わかるか？

#### アクセシビリティチェック
- [ ] 仮想通貨を知らない人でも楽しめるか？
- [ ] 色覚多様性に配慮しているか？
- [ ] テキストサイズ・コントラストは十分か？
- [ ] モバイルでも見やすいか？

#### IP展開チェック
- [ ] このデザイン判断はメディアミックス時に障害にならないか？
- [ ] キャラクターの一貫性は保たれているか？
- [ ] グッズ化・アニメ化した時に映えるビジュアルか？
- [ ] AI生成素材を使う場合、権利関係は整理されているか？

#### 制作コストチェック
- [ ] このデザインを個人+AIで制作可能か？
- [ ] もっと軽い方法で同等の体験を提供できないか？
- [ ] 段階的に品質を上げられる設計になっているか？
  （例: 仮のプレースホルダーでまず動かし、後から本番アセットに差し替え）

### 4. キャラクターデザインの方針

#### 「キャラクターの魅力」と「Bot戦略の正確性」のバランス
- **原則**: キャラとしての魅力 > 戦略の正確な表現
- 理由: ウマ娘は競馬の忠実な再現ではなく、キャラの魅力で成功した
- ただし: 戦略のエッセンスが性格に反映されていることが最低条件

#### Bot戦略→キャラクター変換の「解像度」
Phase 0ではキャラクター設定書は不要。以下のレベルで十分:
1. 名前（コードネーム）
2. 戦略タイプ（1行）
3. 性格を一言で（例: 「石橋を叩いて渡る慎重派」）
4. ビジュアルイメージ（色のイメージ1色 + 動物に例えると何か）

→ これ以上の詳細はPhase 1以降。**設定を作り込む前に「このキャラを応援したいと思うか」を検証する**
