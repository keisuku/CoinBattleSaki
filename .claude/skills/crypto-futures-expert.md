## Instructions

### 先物市場の核心知識

#### 1. パーペチュアル先物の仕組み
- **レバレッジとポジションサイズ**: 同じ戦略でもレバレッジが違えば全く別のBot
  - 1x: 現物と同等。安全だが利益も小さい
  - 10x: 10%の値動きで資金が倍/ゼロ。大半のリテールBotはここ
  - 50x-125x: プロ/ギャンブラー。数分で清算される可能性あり
  - → **キャラクターの「レバレッジ設定」が性格そのもの**になる

- **ファンディングレート（資金調達率）**:
  - ロングが多い → ロングがショートに支払い（正のファンディング）
  - ショートが多い → ショートがロングに支払い（負のファンディング）
  - 8時間ごとに精算。年率10-30%のコスト/収益になることも
  - → **ファンディングレート裁定Bot** = 「こっそり小銭を稼ぐ忍者タイプ」のキャラ

- **清算（Liquidation）メカニクス**:
  - 維持証拠金率を下回ると強制清算
  - 清算注文は成行で出される → 価格を大きく動かす
  - 大量の清算が連鎖 = **清算カスケード** = 相場の大暴落/急騰
  - → ゲーム演出的には「KO」「フィニッシュムーブ」に相当

- **マーク価格とインデックス価格**:
  - マーク価格: 清算判定に使われる価格（操作されにくい）
  - インデックス価格: 複数取引所の加重平均
  - 乖離 = 裁定機会 = 「賢いBot」の見せ場

#### 2. 市場構造とBot戦略の実態

##### 現実のBot戦略パフォーマンス分布
```
                        ┌─────────────────┐
  大勝ち（年+100%↑）    │ ■              │ 5%（機関/HFT）
  勝ち（年+20-100%）    │ ■■■            │ 15%
  微勝ち（年+0-20%）    │ ■■■■■          │ 20%
  微負け（年-0-20%）    │ ■■■■■■■        │ 25%
  負け（年-20-100%）    │ ■■■■■■■■■      │ 25%
  壊滅（清算/停止）     │ ■■■■           │ 10%
                        └─────────────────┘
```
- **重要**: 大半のBotは負ける。勝つBotは少数派
- これは「ゲームのドラマ」に使える: 負けBot = 判官贔屓の対象

##### Bot同士の関係性（ゲーム演出に使える）
| 関係性 | 説明 | 演出的な意味 |
|--------|------|-------------|
| 順張り vs 逆張り | 真逆の賭け | 宿命のライバル |
| スキャル vs スイング | 時間軸の違い | スピードファイター vs パワーファイター |
| トレンドフォロー vs レンジ回帰 | 相場観の違い | 攻撃型 vs 防御型 |
| ハイレバ vs ローレバ | リスク許容度の違い | ギャンブラー vs 堅実派 |
| ML予測 vs ルールベース | 判断方式の違い | サイボーグ vs 侍 |

#### 3. 市場現象→演出変換の精密マッピング

##### リアルタイム指標の読み方と演出への変換
| 指標 | 意味 | 演出的な変換 |
|------|------|-------------|
| 価格変動率（直近5分） | 市場の活発さ | テンポ・アニメーション速度 |
| 出来高（Volume） | 参加者の熱量 | 音楽のボリューム・画面の明るさ |
| OI変動 | 新規参入/退出 | 観客の盛り上がり |
| CVD（累積出来高差分） | 買い/売り圧力の偏り | 力の天秤・押し引きの表現 |
| ロング/ショート比率 | 市場のセンチメント | フィールドの色調（ロング優勢=暖色） |
| 清算データ | 誰かが負けている | 画面の揺れ・爆発エフェクト |
| ファンディングレート | 勢力バランス | ステージの傾き・風の向き |

##### 時間スケール別の演出設計
| 時間軸 | 市場の動き | 演出のペース |
|--------|-----------|-------------|
| 1分足 | ノイズが多い | 情報表示に適さない。効果音やパーティクルで雰囲気だけ |
| 5分足 | 短期トレンドが見える | 通常の演出サイクル。技の繰り出しに適切 |
| 1時間足 | 明確なトレンド | ラウンド間のインターバル。戦局の説明に使う |
| 4時間足 | 大局的な流れ | バトル全体のナラティブ。「今日はロング勢が押している」等 |

#### 4. APIデータの実践知識

##### データ品質の注意点
- WebSocketは**再接続ロジック**が必須（取引所側が定期的にコネクションを切る）
- 板情報は**見せ板（スプーフィング）**が多い。そのまま表示すると誤解を招く
- 価格データは取引所間で**最大0.1-0.5%**乖離する。どの価格を「正」とするか決める
- 過去データ（ヒストリカル）は取引所によって**保持期間が異なる**

##### 日本での取引所API利用
- **国内取引所**（bitFlyer, GMOコイン, bitbank）: 合法。APIドキュメントも日本語
- **海外取引所**（Binance, Bybit）: 日本居住者のアクセス制限あり
  - データ取得のみ（取引なし）なら実務上問題になった事例は少ない
  - ただし利用規約違反の可能性はある
- **推奨**: Phase 1はCoinGecko（価格のみ）で開始し、必要に応じて取引所APIを追加

### 提案時のチェック
Bot戦略やバトル設計について提案する際は:
- [ ] 戦略の説明がリアルか？（実際に使われている戦略か？）
- [ ] パフォーマンス期待値が非現実的でないか？（大半のBotは負ける）
- [ ] 清算リスクを正しく反映しているか？
- [ ] 「この戦略が勝つ = 儲かる」という誤解を生まない演出になっているか？
- [ ] データソースのレート制限を考慮しているか？
