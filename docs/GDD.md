## 0. コンセプト

### ワンライナー
リアルタイムの仮想通貨先物市場データでBotキャラが戦う、
ファンタジースポーツ × パチンコ演出のBot起用バトルゲーム。
Claude Codeで開発された最強Botは、本物の市場で勝てるのか？

### プロダクトの正体
- **ファンタジースポーツ**: ユーザーはBot（選手）を時間帯ごとに起用し、成績で競う
- **ウマ娘**: ニッチな世界（先物市場）をキャラで一般層に届ける
- **パチンコ**: 信頼度段階エスカレーション演出でリアルタイムの値動きを表現
- **リアルデータ**: ゲーム内の全てが本物の市場データで駆動される

### 他サービスとの根本的な違い
- **他（3Commas, Bybit等）**: トレードが前提のツール
- **CoinBattleSaki**: Bot起用判断で競う**ゲーム**。トレード不要

### コア価値
「ゲーム好きだけど暗号資産に触らない人が、ノーリスクで"いかがわしいマネーゲームの世界"を覗き見できるエンターテイメント」
- いかがわしい世界 = 怖いもの見たさの好奇心がフック
- ノーリスク = 自分のお金は1円も動かない
- 暗黙の価値 = 「この通知パターンに慣れたら、本当に先物やる時にも勝てそう」

### メタストーリー
「Claude Codeで最強Botは作れるのか？」
- 開発過程自体がIPの一部
- アプリ内で「CC製」を明示
- SNSで開発過程も配信（アプリへの導線にもなる）

## 2. 世界観

### トーン: ダーク × アンダーグラウンド × 超王道バトル
- SF2初期の「全ジャンル全世界の無差別バトル」の雰囲気
- いかがわしいアンダーグラウンドの世界だが、ねっとりせず爽快
- 清算されても立ち直る。遺恨を残さない

### 環境 = 市場状況
- 雇用統計前後 = 暴風雨の中の戦い
- 平常時 = 公園での穏やかな戦い
- 清算カスケード = 地震/火山噴火
- レンジ相場 = 霧の中の静けさ

### キャラクターの原型
**先物市場の実際の参加者をバトルキャラに翻訳する**:
- ヘッジファンド、オイルマネー、個人投資家、国家権力、取引所

SF2は「世界中の格闘技の頂点」を8キャラに圧縮した。
CoinBattleSakiは「先物市場の参加者の頂点」を8キャラに圧縮する。

> ✅ **翻訳媒介はADR-0008で確定: 「金の世界のアーキタイプ蒸留方式」**
> SF2が格闘技の世界でやったこと（実在の格闘家→普遍的アーキタイプに蒸留）を、
> 金の世界で行う。実在の人物は直接使わず、永続的なアーキタイプに蒸留する。
> トーン: ダーク・大人向け（北斗の拳パチンコ / 牙狼 / 闇金ウシジマくん）
> 人間×非人間の混在OK（牙狼方式）

### キャラデザインの原則（SF2から抽出）
- シルエットだけで誰かわかる
- 色で即座に識別できる
- 戦い方が見た目に直結している
- 全員が全く違う方向性だが、一貫性がある
- 生成AIガチャでは到達不能。深い世界観 → デザイン力 → 画力 → 一貫性の順

## 3. ゲームループ

### ユーザー体験の全体フロー（軍師方式 — ADR-0008）
```
1. 【作戦フェーズ】軍師として作戦を練る
   - Bot編成（8体から選抜、メイン1〜2体が演出の主役）
   - 通貨ペア選択（BTC/ETH/SOL等）
   - レバレッジ設定（リスク×リターン）
   - 資金配分（全賭け or 分散）
2. 【エンジンフェーズ】Botがリアルタイム市場データで自動トレード
3. 📱プッシュ通知「激アツ展開！」（突然のエンカウント）
4. スマホを開く（背徳感）
5. 【演出フェーズ】北斗/牙狼的バトル演出を観戦
   - 小利確 → 雑魚蹴散らし
   - 大ポジション → 強敵バトル
   - 清算カスケード → ボス戦・必殺技
   - 勝利確定後 → 余韻演出（スキップ可）
6. 成績が累積 → ランキングで他ユーザーと競争
7. ハイライト再生 → SNS投稿（バイラル）
8. 日常に戻る → 次の作戦へ
```

### キラーフィーチャー: プッシュ通知 = 突然のエンカウント
- Botが激アツ展開に突入した瞬間に通知
- 市場は24時間365日 → 通知が来るタイミングが予測不能 → 中毒性と背徳感
- 実装: ローカル通知（バックグラウンドでBinance API監視 → サーバー不要）

### 作戦立案（軍師の判断 — ADR-0008）
- バトル前に作戦を立てる。バトル中の介入は不可（見守る快楽に集中）
- 「雇用統計前だからレバ低めで」「今のボラならスキャルBotに全賭け」
- Bot編成 × 通貨ペア × レバレッジ × 資金配分 = 作戦の深さ
- この作戦力がランキング上位への鍵

### ハイライト再生（ADR-0008）
- バトル後、最も印象的な場面を再生可能
- 無料: 1本 / 課金: 最大3本
- 「帰りの電車で今日のバトルを振り返る」体験

### ランキング
- ユーザー同士の成績ランキング（日次/週次/月次）
- 基盤: GameCenter (Apple) / Google Play Games（サーバー不要）
- ランキング対象 = 「稼いだ額」（元手は関係ない）

## 4. ゲーム内経済

### 仮想資金（給料制 — ADR-0008）
- 毎日ログインボーナスで「給料」を支給（仮想通貨）
- ランキング = その日/週/月に稼いだ額（元手は関係ない）
- 全損しても翌日また給料がもらえる
- 現実の「月給で投資する」感覚に近い

### スタミナ制度（ADR-0008）
- Botの1日の稼働回数に制限あり
- 課金で複数体同時稼働やスタミナ回復が可能
- 無料でも1日数回は遊べるバランス

### 勝敗基準（ADR-0008）
- メイン指標: P&L（仮想ポートフォリオの損益）
- サブ指標: 実績称号（連勝、最大利益、生存日数等でアンロック）

### 復活課金
- 全損 → ¥100で即復活
- 無料でも翌日自動復活
- ¥100 = 即復活の時短課金

## 5. 演出方式: パチンコ的信頼度エスカレーション

### 概要
```
値動き発生
  ↓
小さい動き → 「何か来るかも？」予告演出（低信頼度）
  ↓
動きが加速 → 「これは激アツかもしれない！」段階的エスカレーション
  ↓
├── 尻すぼみ → 演出がシュンと消える（よくある値動きだった）
└── 本物の大きな動き → 必殺技発動 / Bot対Botバトル突入
      ├── 清算カスケード → KO演出
      └── 大勝利 → 勝利演出
```

### なぜパチンコ的演出か
- 先物市場の「フェイクアウト（騙し）vs 本物のブレイクアウト」に完全一致
- 95%の退屈な時間問題を解決（小さな動きでも「来るか？来ないか？」で緊張感）
- パッシブ観戦と完全に合致（パチンコも「見てる」のが主体）
- 「激アツ演出が出た！」をスクリーンレコーディングしてSNS投稿するバイラル構造

### SNSバイラルの仕組み
- ユーザーが自発的にアプリ画面を撮影してSNS投稿
- 「アプリの画面自体が撮りたくなるほど面白い」必要がある
- パチンコの激アツ演出をスマホで撮る行動と同じ構造

## 6. キャラクター（Bot）設計

### 設計原則
SF2のキャラデザが30年色褪せない理由:
1. 全世界の格闘技の頂点を、1キャラに圧縮した
2. 深い世界観が先にあって、デザインが生まれた（デザインが先ではない）
3. 8体全部が全く違う方向性なのに、同じ画面に並んでも違和感がない一貫性

### Botの戦い方 = キャラの個性
- スキャルピング型 = 手数が多いが浅い攻撃（百裂脚的）
- スーパーロング型 = 一撃が重いが遅い（ザンギエフ的）
- グリッド型 = 面制圧（ダルシム的リーチ）
- デルタニュートラル型 = 影に潜む（バルログ的）

### Bot進化システム
- 負けたBotは修行して新バージョンとして帰ってくる
- マザーBotから門下生が出てくる（リュウ→ケン→豪鬼の構造）
- Botの改良は開発者がClaude Codeで実際に行い、その過程もコンテンツとして公開

### 課金とBotの関係
- **全Botアクセス無料**（Pay to Winなし）
- 課金はスキン/見た目の変更のみ

## 7. アーキテクチャ

> 詳細は ADR-0005 を参照

### Bot内蔵型（ADR-0005で決定）
```
┌─────────────────────────────────────────────────┐
│          CoinBattleSaki（クライアントサイド）       │
│                                                   │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐    │
│  │ Bot Engine│→│ 8状態変換 │→│ パチンコ的演出 │    │
│  │ (Binance  │  │  レイヤー │  │ + バトル演出  │    │
│  │  API連携) │  │          │  │              │    │
│  └──────────┘  └──────────┘  └──────────────┘    │
│       ↑              ↓              ↓            │
│  Binance API   Bot起用判断     ローカル通知       │
│  (REST)        (ユーザー操作)   (プッシュ通知)     │
│                      ↓                           │
│               GameCenter / Google Play Games      │
│               (ランキング)                        │
│                      ↓                           │
│               localStorage (戦績保存)             │
└─────────────────────────────────────────────────┘
```

- サーバーサイドコード: ゼロ
- ユーザーDB: なし → セキュリティリスク = ゼロ
- 個人情報: 一切保持しない
- ランキング: GameCenter / Google Play Games（サーバー不要）

## 8. マネタイズ

> 詳細は ADR-0004 を参照

### プラットフォーム: App Store / Google Play

### 課金モデル: 完全無料DL + 通知課金 + スキン課金

| 項目 | 価格 | 内容 |
|------|------|------|
| アプリDL | 無料 | 全Bot・全機能アクセス可 |
| プッシュ通知（無料枠） | ¥0 | 1日5回まで |
| プッシュ通知（有料） | ¥1,000/月（将来¥3,000） | 1日30回 |
| 即復活（全損時） | ¥100 | 仮想資金10万円に即復活 |
| キャラスキン | 個別価格 | 見た目のみ変更、性能差なし |

### 通知課金の価値
- 通知なし = アプリを開いて待つだけの時間が長すぎて実質プレイ不能
- 通知あり = 日常生活の中で突然エンカウント（ゲームとして成立）
- ランキング上位勢は全員課金（判断機会が多い = 有利）
- 将来的には「この通知に慣れておけば先物で勝てそう」という深層動機

### 絶対にやらないこと
- ❌ ゲーム内通貨の換金
- ❌ ガチャ
- ❌ 実際の暗号資産を賭けるシステム
- ❌ 投資助言・投資シグナルの提供
- ❌ コピートレード機能
- ❌ 投資成績による成功報酬

## 10. 未解決の設計課題

1. ~~**キャラデザインの翻訳の媒介**~~: ✅ ADR-0008で解決（金の世界のアーキタイプ蒸留方式）
2. **パチンコ演出の信頼度マッピング**: 値動きの大きさ → 信頼度レベル → 演出 の具体的な対応表
3. ~~**勝った先の報酬**~~: → ADR-0006で設計済み（名誉特化1層集中: 称号 + SNS共有カード + 限定スキン（効果なし）。勝利演出→ウイニング画面→共有カードの一連フローも設計済み）
4. **デザインの一貫性**: 生成AIで作る場合の一貫性の保ち方
5. **動画のクオリティ**: チープにならない演出動画の作り方
