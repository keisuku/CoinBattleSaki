## 0. 前提: アーキテクチャ

> 詳細は ADR-0005 を参照

### Bot内蔵型アーキテクチャ（ADR-0005で決定）
CoinBattleSakiはBot engine + エンタメ演出の**全部入り**クライアントサイドアプリ。
BTCsakimonoとの外部API連携は行わない（BTCsakimonoの設計を参考にBot engineを内蔵）。

```
┌─────────────────────────────────────────────┐
│         CoinBattleSaki（クライアントサイド）    │
│                                               │
│  ┌──────────┐  ┌──────────┐  ┌────────────┐  │
│  │ Bot Engine│→│ 8状態変換 │→│ エンタメ演出 │  │
│  │ (市場データ│  │  レイヤー │  │  レイヤー  │  │
│  │  取得+判定)│  │          │  │ (IP/キャラ) │  │
│  └──────────┘  └──────────┘  └────────────┘  │
│       ↑                           ↓          │
│  Binance API              localStorage       │
│  (REST ポーリング)          (戦績保存)         │
└─────────────────────────────────────────────┘
```

### BTCsakimono（参照元）
- URL: https://keisuku.github.io/BTCsakimono/
- index.html 1ファイル（約7,000行）の完全クライアントサイドSPA
- マザーBot 8体 × チャイルド5種 = 最大48体のBot engine
- 4時間で構築された実績 → CoinBattleSakiでも同等の速度で再構築可能
- **CoinBattleSakiはBTCsakimonoのBot engine設計を参考に、エンタメ演出付きで再構築する**

## 1. コンセプト

### ワンライナー
既に稼働中のトレーディングBotの戦績データを、
エンターテイメントとして視覚化・擬人化し、IPとして育てるプロジェクト。

### 設計思想の参照点: ストリートファイター2
SF2を参照するのは「格闘ゲームを作りたい」からではない。
SF2が1992年の厳しい制約下で達成した**設計原則の偉大さ**を、
このプロジェクトの骨格設計に翻訳するため。

**SF2から抽出した設計原則**:
1. **少数精鋭**: 8キャラしかいないが、1人1人がシルエットだけで識別できるほど深い
2. **最小操作×最大表現**: 6ボタン+レバーだけで無限の戦術表現が可能
3. **根本的な差別化**: リュウとダルシムは同じルール上で全く別のゲームを遊んでいる
4. **即座のフィードバック**: 技が当たった/外れた/ガードされたが一瞬でわかる
5. **骨格の強さ**: 演出を全て剥いでも、ゲームとして成立する

**CoinBattleSakiへの翻訳**:
- 少数精鋭 → Bot戦略を「少数の、圧倒的に個性的なキャラクター」に圧縮
- 最小操作×最大表現 → 市場の複雑な動きを「誰でも読めるミニマルな言語」に圧縮
- 根本的な差別化 → RSI逆張りBotとスキャルピングBotは「別の生き物」レベルで違う
- 即座のフィードバック → 市場が動いた→キャラが反応した、が直感的にわかる
- 骨格の強さ → 演出方式（格闘/レース/動画/テキスト）が変わっても成立する骨格

### Phase 0の核心問題
> **「Bot戦略の複雑な市場行動を、SF2が格闘を6ボタンに圧縮したように、
> どんなミニマルな"言語"に圧縮すれば、誰でも直感的に読めて、
> 30年残るフレームワークになるか？」**

この問いに答えることがPhase 0の最優先事項。
演出方式（格闘/レース/動画/テキスト）の選択はその**後**の話。

### 未決定事項（Phase 0で決める）
1. **骨格設計**: Botの行動を表現する「最小言語」は何か？
2. **コアエモーション**: ユーザーに持って帰ってもらう感情は？
3. **演出方式**: 骨格の上に何を乗せるか？
4. **トーン・ターゲット**: 誰に、どんな温度で届けるか？

## 2. 骨格設計: Bot行動の「最小言語」を探す（Phase 0最優先）

### 問い
Bot戦略が市場で行う複雑な行動を、最小いくつの「状態」に圧縮すれば、
知識がない人でも直感的に何が起きているか読め、かつ戦略間の差別化が表現できるか？

### 仮説: Bot行動の基本状態（検証が必要）

| 状態 | 市場的な意味 | 直感的な翻訳 |
|-----|-------------|-------------|
| 観察 | ポジションなし。シグナル待ち | 息を潜めている。じっと見ている |
| 狙撃 | エントリーポイント接近。準備中 | 狙いを定めている。緊張感 |
| 攻撃 | ポジション取得。市場に参加 | 仕掛けた。動き出した |
| 追撃 | 含み益。ポジション追加 | 勢いに乗っている。押している |
| 防御 | 含み損。損切りライン接近 | 耐えている。押されている |
| 撤退 | 損切り実行 | 退いた。ダメージを受けた |
| 勝鬨 | 利確。利益確定 | やった。決まった |
| 崩壊 | 清算。全損 | 倒れた。終わった |

→ この8状態だけで、あらゆるBot戦略の市場行動を表現できるか？
→ 8状態 × キャラ固有の「やり方」 = SF2の6ボタン × キャラ固有の技、に相当

### 検証すべき仮説

#### 仮説0（最重要）: 「8状態モデル」でBotの行動は表現できるか
- 検証方法: BTCsakimonoの既存Bot戦績データから1週間分を取得し、
  全行動を8状態に分類。不自然な分類が出ないか確認
- コスト: ¥0、半日
- 判定基準: 分類不能な行動が全体の10%未満

#### 仮説1: Bot同士の行動の「違い」が状態遷移パターンに現れるか
- 検証方法: BTCsakimonoで稼働中の異なる戦略のBotの状態遷移を並べて比較。
  「別の生き物に見えるか？」を10人に聞く
- コスト: ¥0、半日
- 判定基準: 10人中8人以上が「違う動きをしている」と認識

#### 仮説2: 擬人化すると面白さが増すか
- 検証方法: 同じ状態遷移データを「数値ログ」と「キャラ付き表示」で比較
- コスト: 画像生成AI代のみ、1日
- 判定基準: キャラ付きの方が「また見たい」の割合が高い

#### 仮説3: この骨格は演出方式に依存しないか
- 検証方法: 同じ8状態データを「テキスト」「静止画」「動画」の3方式で表示。
  どの方式でも「何が起きているかわかる」か確認
- コスト: 1-2日
- 判定基準: 全方式で「理解できる」が80%以上

> **鉄則**: 骨格が検証されるまで演出方式を決定しない。コードも書かない

## 3. 演出方式の選択肢（未決定）

### A: リアルタイムゲームエンジン方式（格闘ゲーム/レース等）
```
市場データ → ゲームエンジン(Phaser等) → リアルタイム描画
```
- 開発: 3-6ヶ月（ゲームエンジン経験なしの場合）
- メリット: 没入感が最も高い。「プレイしている」感覚
- デメリット: 開発コスト最大。95%の時間は横ばい相場で退屈になるリスク

### B: 固定演出パターン + 動画生成AI方式
```
市場データ → 状態判定（エントリー/強気/弱気/様子見等） → 対応する固定演出動画を再生
```
- 開発: 1-2週間（動画選択ロジックのみ）
- メリット: 動画AIで高品質な演出を大量生産可能。開発は超軽量
- デメリット: パターンが有限。同じ動画が繰り返される
- **具体的な演出パターン案**:
  - エントリー狙い中: キャラが構えを取る / 目を光らせる
  - 超強気ポジション（ハイレバ）: 技を繰り出す / 吠える / オーラを纏う
  - 様子見: 腕組み / 瞑想 / 相手を観察
  - 自信100%級: 必殺技モーション / 指を鳴らす / 不敵な笑み
  - 損切り: よろめく / 膝をつく / 歯を食いしばる
  - 清算（KO）: 吹き飛ぶ / 画面暗転 / リタイア演出

### C: テキスト実況 + 静止画キャラ方式
```
市場データ → 実況テキスト自動生成 + キャラ表情差分表示
```
- 開発: 1週間
- メリット: 最軽量。キャラの表情差分5枚+テキストだけで成立
- デメリット: 地味。視覚的インパクトが弱い

### D: チャートオーバーレイ方式
```
価格チャート上にキャラの状態アイコン/表情を重ねて表示
```
- 開発: 1-2週間
- メリット: 実用性が高い。TradingView拡張的な価値
- デメリット: 「ゲーム」ではなく「ツール」。IP展開しにくい

### E: ショート動画/SNSコンテンツ自動生成方式
```
1日の戦績 → ハイライト抽出 → 30秒動画を自動生成 → SNS投稿
```
- 開発: 2-4週間
- メリット: バイラル可能性最大。TikTok/YouTube Shorts向け
- デメリット: 「アプリ」ではなく「メディア」。リアルタイム性なし

### F: ハイブリッド方式
```
通常時: C（テキスト+静止画）
ドラマ発生時（清算カスケード等）: B（動画演出）発動
日次: E（ハイライト動画）を自動投稿
```
- 開発: 2-3週間（段階的）
- メリット: メリハリがある。コスト効率が良い
- デメリット: 複数方式の管理が必要

## 6. マネタイズ戦略

> 詳細は ADR-0004 を参照

### コア価値の定義
CoinBattleSakiの本体の価値 = 「勝ってるBotのリアルタイム行動が、エンタメとして可視化される」
- エンタメIP = 認知獲得チャネル（入口の皮）
- コア価値 = リアルタイムBot行動の可視化（本体の骨）
- CoinBattleSaki自体はコピートレード機能を一切持たない

### 体験の軸: 観戦×推し活
- 推しBotを選んで応援する（競馬/スポーツ観戦の構造）
- 操作できないからこそ「応援する」感情が生まれる
- SNSでのシェア・語りがコアループの一部

### プラットフォーム: App Store / Google Play（サーバーゼロ）
- 決済・認証をApple/Googleに完全委任
- サーバーサイドコード: ゼロ
- ユーザーDB: なし → セキュリティリスク = ゼロ
- 個人情報: 一切保持しない

### 課金モデル: 3段ロケット

#### 第1段: 買い切り ¥3,000（Phase 1）
- リアルタイムBot行動の可視化（キャラ演出付き）
- 基本キャラ数体 + 戦績閲覧
- 無料Web版（過去データ/遅延データのみ）で認知獲得

#### 第2段: アプリ内課金 ¥5,000相当（Phase 2）
- プレミアムキャラスキン / 追加キャラ
- 詳細戦績分析（シャープレシオ、ドローダウン等）
- プッシュ通知（清算カスケード等のドラマチックイベント）

#### 第3段: 月額サブスク ¥1,000-3,000/月（Phase 3 検討）
- 高頻度リアルタイムデータ
- 複数Bot同時観戦
- 戦略解説コンテンツ

### 絶対にやらないこと
- ❌ ゲーム内通貨の換金
- ❌ ガチャ（確率表示義務＋社会的リスクが高い）
- ❌ 実際の暗号資産を賭けるシステム
- ❌ 投資助言・投資シグナルの提供（「このBotをコピーしろ」とは絶対に言わない）
- ❌ コピートレード機能の実装
