## 0. コンセプト

### ワンライナー
リアルタイムの仮想通貨先物市場データでBotキャラが戦う、
ファンタジースポーツ × パチンコ演出のBot起用バトルゲーム。

### プロダクトの正体
| 参照元 | CoinBattleSakiでの対応 |
|--------|----------------------|
| ファンタジースポーツ | ユーザーはBot（選手）を時間帯ごとに起用し、成績で競う |
| ウマ娘 | ニッチな世界（先物市場）をキャラで一般層に届ける |
| パチンコ | 信頼度段階エスカレーション演出でリアルタイムの値動きを表現 |
| SF2 | 8体のBotが全く異なる個性で戦い、シルエットだけで識別可能 |

全てが**本物の市場データ**で駆動される。

### 他サービスとの根本的な違い
- **他（3Commas, Bybit等）**: トレードが前提のツール
- **CoinBattleSaki**: Bot起用判断で競う**ゲーム**。トレード不要

### コア価値
「ゲーム好きだけど暗号資産に触らない人が、ノーリスクで"いかがわしいマネーゲームの世界"を覗き見できるエンターテイメント」

- いかがわしい世界 = 怖いもの見たさの好奇心がフック
- ノーリスク = 自分のお金は1円も動かない
- 暗黙の価値 = 「この通知パターンに慣れたら、本当に先物やる時にも勝てそう」

### メタストーリー
「Claude Codeで最強Botは作れるのか？」
- 開発過程自体がIPの一部
- アプリ内で「Claude Code製」を明示
- SNSで開発過程も配信（アプリへの導線にもなる）

## 2. 世界観

### トーン: ダーク × アンダーグラウンド × 超王道バトル
- SF2初期の「全ジャンル全世界の無差別バトル」の雰囲気
- いかがわしいアンダーグラウンドの世界だが、ねっとりせず爽快
- 清算されても立ち直る。遺恨を残さない

### 環境 = 市場状況
市場状態がそのまま戦場の環境になる:
| 市場状態 | 環境演出 |
|---------|---------|
| 雇用統計前後 | 暴風雨の中の戦い |
| 平常時 | 公園での穏やかな戦い |
| 清算カスケード | 地震/火山噴火 |
| レンジ相場 | 霧の中の静けさ |

### キャラクターの原型
**先物市場の実際の参加者をバトルキャラに翻訳する**:
- ヘッジファンド、オイルマネー、個人投資家、国家権力、取引所

SF2は「世界中の格闘技の頂点」を8キャラに圧縮した。
CoinBattleSakiは「先物市場の参加者の頂点」を8キャラに圧縮する。

### キャラデザインの原則（SF2から抽出）
1. シルエットだけで誰かわかる
2. 色で即座に識別できる
3. 戦い方が見た目に直結している
4. 全員が全く違う方向性だが、一貫性がある
5. 深い世界観 → デザイン力 → 画力 → 一貫性の順。生成AIガチャでは到達不能

## 3. ゲームループ

### ユーザー体験の全体フロー
```
1. Botキャラを知る（見た目 + 戦略特性）
2. プッシュ通知「バトル始まった！！」（突然のエンカウント）
3. スマホを開く（背徳感）
4. 「今のBotでいいか？切り替えるか？ノーポジにするか？」（瞬間判断）
5. パチンコ的演出で推しBotの戦いを観戦（推しBot固定視点）
    → 信頼度段階エスカレーション
    → 尻すぼみ or 大爆発（必殺技/Bot対Botバトル/KO）
6. 成績が累積 → ランキングで他ユーザーと競争
7. SNSでアプリ画面を撮影して投稿（バイラル）
8. 日常に戻る → 1に戻る
```

### キラーフィーチャー: プッシュ通知 = 突然のエンカウント
- Botがポジションを取った瞬間に通知
- 市場は24時間365日 → 通知が来るタイミングが予測不能 → 中毒性と背徳感
- 通知が来たら即座にBot起用判断が求められる
- 実装: ローカル通知（バックグラウンドでBinance API監視 → サーバー不要）

### Bot起用判断
- リアルタイムでいつでも「ノーポジ / BotA / BotB / BotC...」を切り替え可能
- 「雇用統計前だからノーポジにしよう」「今のボラティリティならスキャルBotだ」
- この判断力がランキング上位への鍵

## 4. ゲーム内経済

### 仮想資金
- 毎日10万円（仮想通貨）のお小遣いが配布される
- ランキング = その日/週/月に稼いだ額（元手は関係ない）
- 全損しても翌日また10万円もらえる

### ランキング
- ユーザー同士の成績ランキング（日次/週次/月次）
- 基盤: GameCenter (Apple) / Google Play Games（サーバー不要）
- ランキング対象 = 「稼いだ額」

### ランキング報酬: 名誉特化（機能報酬なし）
「クラウディングアウト効果」を回避するため、報酬は名誉のみ:

| 報酬カテゴリ | 内容 |
|-------------|------|
| 称号 | 月間ランキング順位に応じた称号（「月間覇者」等） |
| SNS共有カード | 成績カード画像を自動生成。アプリ名・Bot名入り（バイラル装置） |
| 限定スキン | ランキング上位者限定のBot見た目変更（性能差なし） |
| ランキングバッジ | 累計実績に応じたプロフィール装飾 |

## 5. 演出方式: パチンコ的信頼度エスカレーション

### なぜパチンコ的演出か
- 先物市場の「フェイクアウト（騙し）vs 本物のブレイクアウト」に完全一致
- 95%の退屈な時間問題を解決（小さな動きでも「来るか？来ないか？」で緊張感）
- パッシブ観戦と完全に合致（パチンコも「見てる」のが主体）
- 「激アツ演出が出た！」をスクリーンレコーディングしてSNS投稿するバイラル構造

### 8状態変換レイヤー（σベース閾値）

| # | 状態名 | σ閾値 | 概要 | 演出 |
|---|--------|-------|------|------|
| S1 | 凪 | σ < 0.5 | 何も起きていない | Botアイドルアニメ、マイクロイベント |
| S2 | 気配 | σ > 0.5 | 微かな予兆 | 「何か来るかも？」背景微変化 |
| S3 | 胎動 | σ > 1.0 | 予告演出 | 緑の保留球。「動き出した...！」 |
| S4 | 激突 | σ > 1.5 | バトルモード突入 | 赤。分割画面でBot対決 |
| S5 | 激アツ | σ > 2.0 | スクショ映え圏内 | 金の演出。「激アツ！！」 |
| S6 | 覚醒 | σ > 2.5 | 覚醒トランスフォーメーション | 虹。沈黙→インパクト |
| S7 | 臨界 | σ > 3.0 | 確定音 | 必殺技 → 勝利フロー or KO |
| S8 | 尻すぼみ | S3以上から反転 | コメディ演出で凪に復帰 | 60-70%の確率で発生 |

### シグナルスタッキング（パチンコの「複数予告重なり」）
パチンコの「ロゴ予告 + 金文字 + キャラ出現 → 激アツ！」を再現:
- 出来高スパイク × 複数Botが同方向 × FR（ファンディングレート）極端
- 重なるほど上位状態への遷移確率が上昇

### 確定音設計
- S7（臨界）到達時に「確定音」を鳴らす
- パチンコの確定音と同じ心理効果（「キタ！」の瞬間）
- Bot毎に固有の確定音を持つ

### 95%退屈問題の解決
- S1/S2でもマイクロイベントで「見てしまう」設計
- ちびマスコット神獣のアイドルアニメーション
- Bot同士の雑談/日常会話
- 過去の戦績フラッシュバック

## 6. キャラクター（Bot）設計

### 翻訳媒介: 「トレーダー × 神獣（守護霊獣）」
トレーディング戦略をバトルキャラに翻訳する媒介:
- **トレーダー（人間）** = 感情移入の器
- **神獣（霊獣）** = 戦闘ビジュアルの器（ペルソナ/スタンド/尾獣型）
- 構造: SF2の「国 × 格闘技」= 本作の「時間軸 × 神獣 × 戦法」

### 尾獣メカニクス（神獣の段階的巨大化）

| 通常 | S1-S2 | ちびマスコット（肩に乗るサイズ） |

- ランキング: GameCenter / Google Play Games（サーバー不要）
- 戦績: localStorage保存

- マザーBot 8体 + チャイルドバリアント各5体 = 計40体
- 元コードベース（BTCsakimono）: 7,000行のHTML単一ファイル

- 通知なし = アプリを開いて待つだけの時間が長すぎて実質プレイ不能
- 通知あり = 日常生活の中で突然エンカウント（ゲームとして成立）
- ランキング上位勢は全員課金（判断機会が多い = 有利）

### 絶対にやらないこと
- ゲーム内通貨の換金
- ガチャ
- 実際の暗号資産を賭けるシステム
- 投資助言・投資シグナルの提供
- コピートレード機能
- 投資成績による成功報酬

## 9. 演出技術方針

### チープにならないための原則
1. **レイヤード・モーション**: 背景 + エフェクト + キャラ + UIを別レイヤーで動かす
2. **ディズニー12原則の適用**: スクワッシュ&ストレッチ、予備動作、アーク等
3. **緩急のメリハリ**: 95%の静けさが5%の爆発を際立たせる
4. **音の設計**: 確定音、環境音、SE の3層構造

### 技術オプション（未確定）
- Live2D的パーツアニメーション
- CSS/SVGアニメーション
- Canvas 2Dパーティクル
- 上記の組み合わせ

### 音声設計方針
| 状態 | 音の性質 |
|------|---------|
| S1 凪 | 環境音のみ。静寂 |
| S2 気配 | 低い持続音が加わる |
| S3 胎動 | リズムが生まれる。心拍音 |
| S4 激突 | バトルBGM開始 |
| S5 激アツ | BGM変調。テンポアップ |
| S6 覚醒 | 一瞬の沈黙 → 轟音 |
| S7 臨界 | 確定音 → 必殺技SE |
| S8 尻すぼみ | コミカルSE。「ズコー」 |

## 10. SNSバイラル設計

### 仕組み
- S5（激アツ）以上がスクショ/画面収録映え圏内
- ユーザーが自発的にアプリ画面を撮影してSNS投稿
- 「アプリの画面自体が撮りたくなるほど面白い」必要がある
- パチンコの激アツ演出をスマホで撮る行動と同じ構造

### SNS共有カード
勝利時に自動生成される成績カード:
- Bot名 + 神獣イラスト
- 損益結果
- アプリ名（バイラル装置として機能）
- ワンタップでSNS投稿可能
