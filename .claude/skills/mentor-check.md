# ゲーム開発メンターチェック Skill

## Description
新機能・設計変更の前に、経験豊富なゲーム開発メンターとして多角的にレビューする。
ユーザーに言わなくても、内部的に必ずこのチェックを通してから提案する。

## Instructions

### 自動トリガー条件
- 新機能の提案・実装時
- 技術選定の変更時
- 外部API・ライブラリの導入時
- マネタイズ関連の設計時
- キャラクター・ストーリー関連の設計時

### チェック項目

#### 1. 法律・コンプライアンス
- [ ] 金商法: 投資助言・投資運用業に該当しないか
- [ ] 賭博罪: ゲーム内通貨の換金性が生まれないか
- [ ] 景品表示法: 過大景品・優良誤認・有利誤認がないか
- [ ] 資金決済法: 前払式支払手段の届出義務が発生しないか
- [ ] 個人情報保護法: ユーザーデータの取り扱い
- [ ] 特定商取引法: 有料サービスの表示義務
- [ ] 著作権・商標: 使用する素材・名称の権利関係

#### 2. 技術的実現可能性
- [ ] 個人+AIで実装可能なスコープか
- [ ] 既存アーキテクチャとの整合性
- [ ] パフォーマンスへの影響
- [ ] 後からの変更コスト（やり直しリスク）

#### 3. ビジネス・IP戦略
- [ ] 使用ライブラリ・データのライセンスが商用利用可能か
- [ ] メディアミックス展開時に障害にならないか
- [ ] キャラクターIPとしての整合性

#### 4. ユーザー体験
- [ ] ターゲットユーザーにとって価値があるか
- [ ] 競合との差別化ポイント
- [ ] 初見でもわかるUI/UXか

#### 5. リスク対策
- [ ] 最悪のシナリオは何か
- [ ] リスク軽減策はあるか
- [ ] 撤退可能か（取り返しがつくか）

### Output Format
```
## メンターチェック結果
### 判定: ✅ 進めてOK / ⚠️ 要検討 / 🛑 ストップ

### ポジティブフィードバック
- この部分は良い: ...

### リスク指摘
- 🔴 法律: ...
- 🟡 技術: ...
- 🔵 ビジネス: ...

### 参考事例
- 「○○」ではこうしている: ...

### 推奨アクション
1. ...
```
