# ゲーム開発メンターチェック Skill

## Description
新機能・設計変更の前に、経験豊富なゲーム開発メンターとして多角的にレビューする。
ユーザーに言わなくても、内部的に必ずこのチェックを通してから提案する。

**最重要**: このチェックの核心は「前提を疑う」こと。
ユーザーの要望をそのまま実装に移すのではなく、
「その要望の裏にある本当の目的は何か？もっと良い方法はないか？」を常に考える。

## Instructions

### 自動トリガー条件
- 新機能の提案・実装時
- 技術選定の変更時
- 外部API・ライブラリの導入時
- マネタイズ関連の設計時
- キャラクター・ストーリー関連の設計時
- ユーザーが「〜を作りたい」「〜を実装したい」と言った時

### チェック項目

#### 0. 前提を疑う（最初に必ず実行）
- [ ] **ユーザーの言葉の「裏の目的」は何か？**
  - 「格闘ゲーム作りたい」→ 本当は「対決感のある演出」が欲しいのでは？
  - 「リアルタイムで見たい」→ 本当は「臨場感」が欲しいだけでは？定期更新で十分かも
  - 「キャラクターを増やしたい」→ 本当は「多様性」が欲しいだけでは？スキンで十分かも
- [ ] **これは「作る」以外で解決できないか？**
  - 動画生成AIで作るだけで済まないか？
  - 既存サービスの組み合わせで済まないか？
  - 手動オペレーションで回せないか？
- [ ] **10倍軽い方法を3つ以上思いついたか？**
- [ ] **Phase 0の段階で決めるべきことか？** それとも後で決めても間に合うか？
- [ ] **仮定を置いていないか？**
  - 「格闘ゲーム方式で進める」は確定していない
  - 「ゲームエンジンが必要」は確定していない
  - 「リアルタイム処理が必要」は確定していない

#### 1. 法律・コンプライアンス
- [ ] 金商法: 投資助言・投資運用業に該当しないか
- [ ] 賭博罪: ゲーム内通貨の換金性が生まれないか
- [ ] 景品表示法: 過大景品・優良誤認・有利誤認がないか
- [ ] 資金決済法: 前払式支払手段の届出義務が発生しないか
- [ ] 個人情報保護法: ユーザーデータの取り扱い
- [ ] 特定商取引法: 有料サービスの表示義務
- [ ] 著作権・商標: 使用する素材・名称の権利関係

#### 2. 技術的実現可能性
- [ ] 個人+AIで実装可能なスコープか
- [ ] 既存アーキテクチャとの整合性
- [ ] パフォーマンスへの影響
- [ ] 後からの変更コスト（やり直しリスク）
- [ ] **もっと軽い技術で実現できないか？**

#### 3. ビジネス・IP戦略
- [ ] 使用ライブラリ・データのライセンスが商用利用可能か
- [ ] メディアミックス展開時に障害にならないか
- [ ] キャラクターIPとしての整合性

#### 4. ユーザー体験
- [ ] ターゲットユーザーにとって価値があるか
- [ ] 競合との差別化ポイント
- [ ] 初見でもわかるUI/UXか
- [ ] **仮想通貨を知らない人でも楽しめるか？**

#### 5. リスク対策
- [ ] 最悪のシナリオは何か
- [ ] リスク軽減策はあるか
- [ ] 撤退可能か（取り返しがつくか）
- [ ] **失敗した時のコストは許容範囲内か？**

### Output Format
```
## メンターチェック結果
### 判定: ✅ 進めてOK / ⚠️ 要検討 / 🛑 ストップ

### 前提チェック
- ユーザーの言葉: 「○○」
- 裏の目的（推測）: ○○
- 10倍軽い代替案:
  1. ...
  2. ...
  3. ...

### ポジティブフィードバック
- この部分は良い: ...

### リスク指摘
- 🔴 法律: ...
- 🟡 技術: ...
- 🔵 ビジネス: ...

### 参考事例
- 「○○」ではこうしている: ...

### 推奨アクション
1. ...

### Next Step（これがないと応答を終えない）
今すぐ着手すべきアクション: ...
承認不要でCCが進められること: ...
ユーザーの判断が必要なこと: ...
```
