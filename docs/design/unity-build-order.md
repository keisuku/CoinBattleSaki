# CoinBattleSaki — ゼロからの構築順序（Unity + アセット + AI + ミドルウェア）

## 前提の整理

### 確定している事実
- 設計ドキュメント: 100%完成（GDD, ADR 7本, キャラ8体, 演出マッピング）
- HTMLプロトタイプ: UI参考のみ。コードは使い捨て
- Unity経験: ゼロ（Claude主導でC#/シーン生成、ユーザーがEditor操作）
- 筐体デザイン: 仮説段階（「楽しいかどうか」が最優先）

### 最重要原則
> **「演出の設計図（シーケンス）」を先に作る**
> アセットは「素材+動き」の短縮手段。真価は「組み合わせ」にある。
> 時短 = アセット + AI + ミドルウェアの三位一体。

### 致命的な問い（Phase 0で検証すべきこと）
> 「Botが自動売買する様子をパチンコ演出で見るのは、本当に楽しいのか？」

この問いに答えないまま Unity に進むのは危険。
Phase 0 は Unity を使わずにこの問いを検証する。

---

## Phase 0: 体験の核心を検証する（Unity不要）

### 目的
筐体デザインもUIレイアウトも「手段」。
先に「S1凪→S3胎動→S5激アツ→S7臨界の体験」が面白いかを確認する。

### 0-1: 演出スコア（楽譜）を作る

パチンコの開発現場では「演出仕様書」が全ての起点。
本ゲームの演出スコアとは：

```
Time 0:00  [S1 凪]
  画面: 暗い。ちび鳳凰が肩で居眠り。価格がゆっくり動く
  音: アンビエントBGM。遠いタイピング音
  感情: 退屈だが、不思議と離れられない

Time 3:00  [S2 気配]
  画面: 鳳凰の目が開く。画面端に青いシマー
  音: 低いping音が1回
  感情: 「ん？」

Time 5:00  [S3 胎動]
  画面: 緑の予告。鳳凰が実体化（60cm）。サラが構える
  音: 心拍BGMに遷移。テンション曲開始
  テキスト: 「動き出した...！」
  感情: 「来るか？来るのか？」

Time 8:00  [選択肢A: S4→S5→S7 当たりルート]
  画面: 赤→金→虹へエスカレーション。鳳凰が巨大化
  音: バトルBGM→激アツBGM→確定音
  感情: 脳汁。スクショ。「うおおおお！」

Time 8:00  [選択肢B: S8 尻すぼみルート（70%の確率）]
  画面: 一瞬で脱色。鳳凰がぷしゅーっと縮む
  音: 「しゅぅぅ...」デフレーションSE
  テキスト: 「...フェイクか。次こそは。」
  感情: 笑い。「またかよ！でも次こそ...」
```

**これをテキストで完成させる。** ADR-0007のPart 9にシナリオ例があるので、それを拡張する。

### 0-2: 「体験PV」を作る（AI動画 or スライドショー）

演出スコアを元に、以下の方法で「体験の味見」を作る：

| 方法 | ツール | 所要時間 | 精度 |
|------|--------|---------|------|
| **A: AIスライドショー** | ChatGPT画像生成 + Canva/PowerPoint | 1-2日 | 中 |
| **B: AI動画** | Runway / Kling / Sora | 2-3日 | 高 |
| **C: 既存パチンコ動画の再編集** | YouTube素材 + 編集ソフト | 半日 | 低（参考のみ） |

**推奨: A（AIスライドショー）**
- ChatGPTで各状態の画面イメージを生成（Phase 1のプロンプト改修して使用）
- 時系列で並べてBGM付きスライドショーにする
- 「これを見て楽しいか？」を自分で判断

### 0-3: 筐体 vs 非筐体の比較

「筐体にするかどうか迷っている」ので、2パターンの画像を生成して比較：

| パターン | コンセプト | 画像生成で確認 |
|---------|----------|-------------|
| **A: 筐体型** | スマホ全体がパチンコ台。メタリック枠。物理ボタン感 | ui-image-prompts.md のPrompt 1-G |
| **B: フルスクリーン型** | 枠なし。画面全体がコンテンツ。モダンなゲームUI | 別途プロンプト作成 |
| **C: ハイブリッド型** | 普段は枠なし。S4以上で枠が出現して光る | 別途プロンプト作成 |

**Phase 0の判定基準:**
- [ ] 「S1→S3→S5→S7の流れ」を見て興奮するか？
- [ ] 「S8の尻すぼみ」で笑えるか、イラつくか？
- [ ] 筐体 vs フルスクリーン、どちらがワクワクするか？
- [ ] 「これをスマホで毎日開きたい」と思えるか？

→ 全てYESならPhase 1へ。NOがあれば設計に戻る。

## Phase 1: 最小の「楽しい」を作る（Unity MVP）

### 目的
SARAH 1体だけで、S1→S3→S5→S7（＋S8）が動く最小デモ。
**リアルBinanceデータ接続。** 仮データではない。

### 何を買う・入れる（この順番で）

| # | ミドルウェア/アセット | 目的 | 費用目安 | 必須度 |
|---|---------------------|------|---------|-------|
| 1 | **DOTween Pro** | UI/演出アニメの全て。これなしでは何も動かない | $15 | ★★★ |
| 2 | **TextMeshPro** | 「激アツ！！」等のインパクトテキスト | 無料(Unity内蔵) | ★★★ |
| 3 | **VFXパーティクルパック** | 光・爆発・スパーク・画面フラッシュ | $10-30 | ★★☆ |
| 4 | **ダークUI素材パック** | ボタン・パネル・ゲージの土台 | $10-20 | ★★☆ |
| 5 | **PlayMaker** | 8状態の遷移を視覚的に構築（初心者向け） | $65 | ★★☆ |

**Phase 1では買わないもの:**
- Spine（キャラアニメ → Phase 2以降。Phase 1はスプライト差し替えで十分）
- CRIWARE（音の精密同期 → Phase 2以降。Phase 1はUnity標準AudioSourceで十分）
- 有料キャラアセット（AI生成の仮素材で検証）

### 構築順序（Phase 1の中の順番）

```
Week 1: 土台
  ├── Unityプロジェクト作成（Claude がフォルダ構成・設定ファイル生成）
  ├── DOTween Pro 導入
  ├── Binance REST APIクライアント（C#）
  └── ローソク足データ取得 → 画面に表示

Week 2: 状態エンジン
  ├── σ計算エンジン（ローリング48本の標準偏差）
  ├── 8状態マシン（PlayMaker or C# FSM）
  ├── S1⇔S2⇔S3 遷移（σ閾値で自動判定）
  └── S8（尻すぼみ）検知（50%リトレース）

Week 3: 見た目
  ├── 画面レイアウト（Phase 0の判定結果に基づく）
  ├── 状態ごとの画面変化（色・光・テキスト）
  ├── DOTweenシーケンスで遷移アニメ
  └── AI生成の仮キャラ画像を配置

Week 4: 音と統合
  ├── 状態ごとのBGM切り替え（フリー素材）
  ├── 確定音（仮）
  ├── S8デフレーションSE
  └── SARAH 1体で通しプレイ → 「楽しいか？」判定
```

### Phase 1の判定基準
- [ ] リアルBTCデータでS1→S2→S3が自然に発生する
- [ ] S3から70%の確率でS8（尻すぼみ）が起きて「笑える」
- [ ] S5以上まで到達した時「興奮する」
- [ ] 確定音が鳴った瞬間に脳汁が出る
- [ ] 30分放置しても「そろそろ見たい」と思える

## Phase 2: キャラクターに命を吹き込む

### 目的
SARAH以外の7体を追加。キャラごとの個性が演出に出る。

### この段階で追加するもの

| # | ミドルウェア/アセット | 目的 |
|---|---------------------|------|
| 1 | **Spine Essential** | キャラアニメーション。パーツ分け式でちび→巨大を表現 |
| 2 | **CRIWARE ADX2 LE** | BGMクロスフェード、フレーム精密SE同期 |
| 3 | **キャラ立ち絵** | AI生成 → 手修正 → Spine用パーツ分け |
| 4 | **神獣デザイン** | ちびフォーム8体 + S7最大フォーム8体 |

### AI生成の使い方

| 素材 | 生成AI | 後処理 |
|------|--------|--------|
| キャラ立ち絵（コンセプト） | Midjourney / PixAI | 手修正で統一感 |
| 神獣ちびフォーム | ChatGPT + Midjourney | Spine用にパーツ分解 |
| 背景（4天候 × 昼夜） | Stable Diffusion | 色調補正 |
| エフェクトテクスチャ | Midjourney | アルファチャンネル追加 |
| BGM | Suno / Udio | ループポイント編集 |
| SE | Freesound + AI | CRIWARE用に整形 |

### 構築内容

```
8キャラのBot定義（ScriptableObject）
  └── 各Botの売買ロジック実装
  └── キャラ固有の演出分岐
  └── Bot切り替えUI
  └── 複数Bot同時稼働
  └── スタッキングシステム（複数Bot同方向 → Trust加算）
```

### 目的

### 内容

| カテゴリ | 内容 |

| **課金** | 通知サブスクリプション（¥1,000/月）。スキンIAP |

| **最適化** | モバイルパフォーマンス。バッテリー消費。メモリ管理 |

## 最も重要な1文

> **Phase 0（体験の検証）を飛ばしてUnityに入らないこと。**
>
> 「筐体が楽しいか」「パチンコ演出が楽しいか」「S8で笑えるか」
> これらの答えが出る前にアセットを買っても無駄になる。
>
> Phase 0のコストはゼロ（AI画像生成 + テキスト）。
> Phase 1のコストは$100+と数週間の作業。
> 順番を間違えると全て作り直しになる。
