# ADR-0006: ランキング報酬設計

## ステータス: 提案（議論中）

## コンテキスト

GDD未解決課題 #3「勝った先の報酬」。

ランキング上位に何を用意するか。ユーザーがBot起用判断を磨き、
ランキングで上位に入った時に「報われた」と感じる仕組みが必要。

### 制約条件（絶対に破れないもの）
1. **サーバーゼロ**: GameCenter / Google Play Gamesで完結
2. **換金不可**: ゲーム内の何も現金と交換できない
3. **Pay to Winなし**: 報酬が「勝率の保証」になってはならない
4. **投資助言の禁止**: 報酬が投資シグナルになってはならない
5. **法的リスク回避**: 景品表示法、賭博罪に抵触しない
6. **個人開発で運用破綻しない**: 物理的な景品発送等は不可

### なぜ報酬設計が重要か
- ランキングがあっても「だから何？」では継続しない
- パチンコの出玉 = 景品交換所がある。本ゲームにはそれがない
- ファンタジースポーツには賞金がある。本ゲームには賞金がない
- **「勝つこと自体が楽しい」だけで回るか？** が核心の問い

---

## 分析: 先行事例の報酬構造

### 1. ゲーム内完結型（換金なし）
| 事例 | 報酬 | 動機 |
|------|------|------|
| ウマ娘 | 限定称号・限定衣装・育成素材 | コレクション欲・推し愛 |
| Apex Legends | ランクバッジ・ダイブ軌道・限定スキン | 見せびらかし（社会的証明） |
| ポケモンGO | ランク報酬（ほしのすな等） | 育成効率アップ |
| 将棋ウォーズ | 段位・称号 | 実力の証明 |

### 2. リアル報酬型
| 事例 | 報酬 | 動機 |
|------|------|------|
| ファンタジースポーツ（DraftKings等） | 賞金 | 金銭的動機 |
| eスポーツ | 賞金・スポンサー | 名誉 + 金銭 |

### 3. 本ゲームが取れる道
- リアル報酬（賞金） → **不可**（賭博規制・投資助言リスク）
- ゲーム内報酬 → **可能**（サーバーゼロでも実現可能な範囲で）

---

## 提案: 3層の報酬設計

### 第1層: 社会的証明（承認欲求）— 最重要

**「俺は先物の世界で勝てる人間だ」という自己認識の獲得**

これがCoinBattleSaki独自の最大報酬。他のゲームでは得られない。

| 報酬 | 内容 | 実装 |
|------|------|------|
| **ランク称号** | 月次成績で段位付与（「鬼殺し」「相場師」「伝説のディーラー」等） | ローカル保存 + GameCenter表示名 |
| **累積戦績** | 通算勝率・最高記録・連勝記録がプロフィールに刻まれる | ローカル保存 |
| **SNS共有カード** | 成績をOGP画像として生成し、X/Instagram等に投稿可能 | クライアントサイド画像生成 |
| **ランキング順位バッジ** | 「月間Top10」「週間1位」等のバッジがプロフィールに永久表示 | ローカル保存 |

なぜこれが効くか:
- 「先物で勝てる判断力がある」は、ゲーム外でも社会的価値を持つ
- X等で戦績を共有 → 「すごい」「教えて」と反応がある → 承認欲求が満たされる
- パチンコの「出玉報告」と同じ構造（パチンコの出玉もSNSで報告する層が存在する）
- バイラル効果: 成績共有 = アプリの宣伝 = 新規ユーザー獲得

#### ランク称号の段階設計（案）

```
月次成績ベース（仮想資金10万円スタート）:

  損失（マイナス）    → ランクなし
  ¥0〜¥50,000       → 見習い
  ¥50,001〜¥200,000  → 相場読み
  ¥200,001〜¥500,000 → 仕手筋
  ¥500,001〜¥1,000,000 → 相場師
  ¥1,000,001以上      → 伝説のディーラー

  特殊称号（条件付き）:
  - 「不敗」: 月間の全損ゼロ
  - 「鬼殺し」: 暴落相場で月間プラス
  - 「千里眼」: 月間Top10を3ヶ月連続
  - 「神の手」: 月間1位
```

### 第2層: ゲーム内機能報酬（プレイ体験の拡張）

| 報酬 | 内容 | 条件 | 実装 |
|------|------|------|------|
| **限定スキンアンロック** | 課金では買えない限定キャラスキン | 月間Top100 | ローカル保存 |
| **演出カスタマイズ** | 勝利演出・KO演出の特別版 | 週間Top10 | ローカル保存 |
| **Bot試用権** | 開発中の新Botを先行利用 | 月間Top50 | ローカルフラグ |
| **仮想資金ボーナス** | 翌月の開始資金が15万円（通常10万円） | 月間Top30 | ローカル保存 |
| **通知枠ボーナス** | 翌月の無料通知枠が10回（通常5回） | 週間Top50 | ローカル保存 |

設計意図:
- **限定スキン = 「課金では手に入らない」が重要**。実力の証明になる
- **仮想資金ボーナス = 微妙に有利だがPay to Winにならないライン**
  - 15万 vs 10万 = 1.5倍だが、腕が悪ければ全損は同じ
  - 「上手いやつがさらに有利」は格ゲーのランクマッチと同じ構造
- **通知枠ボーナス = 課金への自然な導線**
  - 「10回でもこんなに便利なら、30回の課金版はもっと…」

### 第3層: メタ報酬（コミュニティ・IP）— 将来施策

| 報酬 | 内容 | 実装時期 |
|------|------|---------|
| **殿堂入り** | 歴代月間チャンプがアプリ内に永久掲載 | Phase 2以降 |
| **Bot命名権** | 新Botの名前を月間1位が提案できる | Phase 2以降 |
| **開発参加権** | 月間Top10が次のBot戦略の方向性に投票できる | Phase 3以降 |
| **リアルグッズ** | 年間チャンプに限定グッズ送付 | Phase 4以降（IP確立後） |

設計意図:
- Phase 1では第1層 + 第2層のみで運用
- コミュニティが成長したらメタ報酬を追加
- 「Bot命名権」はコスト0で強い動機づけ（自分の名前がゲームに残る）
- 運営コスト最小でインパクト最大を追求

## 核心の問い: 「勝つこと自体が楽しい」で回るか？

### 回答: 回る。ただし条件付き。

CoinBattleSakiが「勝つだけで楽しい」ゲームになる条件:

1. **勝ちの実感が派手であること**
   - パチンコ的演出が必須。地味な数字の増加だけでは回らない
   - 「やったぁぁぁ！」と声が出る瞬間が必要 → 演出設計の課題と直結

2. **勝ちを人に見せられること**
   - SNS共有カードの質が極めて重要
   - 「この画面を見せたらすごいと思われる」デザインが必要
   - スクショ映えするUI = バイラルの起点

3. **勝ちの記録が残ること**
   - 累積戦績が消えない。自分の成長が可視化される
   - 「半年前は見習いだったのに今は相場師だ」

4. **負けが致命的でないこと**
   - 翌日10万円リセットは既にこれを実現している
   - 清算されても「まぁ明日もらえるし」→ 気軽に再挑戦

### パチンコとの比較

| | パチンコ | CoinBattleSaki |
|--|---------|----------------|
| 中毒性の源泉 | 演出 + 出玉（金銭） | 演出 + ランキング + 承認 |
| 金銭報酬 | あり（景品交換所） | なし |
| 承認報酬 | 弱い（SNS投稿する層は少数） | 強い（SNS共有が設計に組み込まれている） |
| 復帰コスト | 高い（実費） | ほぼゼロ（翌日無料リセット or ¥100） |

**結論: 金銭報酬の欠如を「承認報酬の強化」で補う設計。**

## 不正対策

サーバーゼロ = 不正検知が困難。以下で対策:

### ローカル改ざんリスク
- ランキングデータがGameCenter/Google Play Games依存
- GameCenter/Google Play Gamesは端末署名ベースなので完全な改ざんは困難
- ただし脱獄端末等での改ざんリスクは残る

### 対策方針
1. **「稼いだ額」のスコア送信時に妥当性チェック**
   - Binance APIの実データと照合（ローカルで）
   - 理論上ありえない利益額は弾く
2. **異常検知**
   - 月間利益が理論上限を超えるスコアを非表示にする閾値設定
   - 例: 100倍レバ × 全額 × 最大ボラティリティでも到達不能な額は弾く
3. **Phase 2以降**: コミュニティ通報 + 手動BAN（サーバー必要）

### 割り切り
- Phase 1ではローカル妥当性チェックのみ
- 少数の不正者よりゲーム体験の質を優先
- 「不正して1位取っても金銭的見返りがない」のが最大の抑止力

## リスク

1. **「報酬がショボい」と思われる**
   → 対策: 第1層（承認欲求）の質を極限まで高める。SNS共有カードの映え
2. **不正でランキングが崩壊する**
   → 対策: Phase 1は閾値チェックのみ。金銭報酬がないので不正動機が弱い
3. **ランキング上位が固定化する**
   → 対策: 日次/週次ランキングで新規参入の余地を残す。月次は実力者向け
4. **仮想資金ボーナスがPay to Winと見なされる**
   → 対策: 差は1.5倍に抑え、上位維持には実力が必須な設計にする

## 代替案（検討の上、却下）

1. **暗号資産を報酬にする** → 賭博罪リスク。法的に不可
2. **Amazon/iTunes ギフト券** → サーバー必要 + 運営コスト + 景品表示法
3. **報酬なし（ランキングのみ）** → 継続動機が弱すぎる
4. **NFTバッジ** → 法的リスク + ターゲット層（暗号資産未経験者）に合わない
5. **広告報酬（動画広告を見ると復活）** → UX劣化。世界観と合わない
