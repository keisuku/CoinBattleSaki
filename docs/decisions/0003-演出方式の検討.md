# ADR-0003: 演出方式の検討

## ステータス: 提案中（Phase 0で検証後に決定）

## コンテキスト
「ストリートファイター2風」というイメージワードが出発点だが、
格闘ゲームを作ることが本当に最善かは未検証。

上流の目的は「Botのトレーディングパフォーマンスを面白く見せる」ことであり、
その手段として格闘ゲームUI以外にも選択肢がある。

Phase 0では、以下の観点で最適な演出方式を決定する必要がある:
1. 開発コスト（個人+AIで実現可能か）
2. エンターテイメント性（見ていて面白いか）
3. IP展開可能性（キャラクターとして魅力的か）
4. 技術的実現性（Phase 1で動くものが作れるか）
5. バイラル可能性（SNSで広まるか）

## 決定: 未決定

## 選択肢の比較

### A: リアルタイムゲームエンジン（格闘ゲーム/レース等）
| 観点 | 評価 | コメント |
|------|------|---------|
| 開発コスト | ★★★★★ | Phaser/PixiJS経験なしで3-6ヶ月 |
| エンタメ性 | ★★★★★ | 完成すれば最も面白い |
| IP展開 | ★★★★ | キャラが動くのでIPとして映える |
| 技術実現性 | ★★ | ゲームエンジン+リアルタイムデータ同期が難関 |
| バイラル性 | ★★★ | 配信向きだがアプリDLが必要 |
| **総合リスク** | **高** | 完成しないリスクが最も大きい |

### B: 固定演出パターン + 動画生成AI
| 観点 | 評価 | コメント |
|------|------|---------|
| 開発コスト | ★★ | 動画選択ロジックのみ。1-2週間 |
| エンタメ性 | ★★★★ | 動画品質次第。動画AIの進歩で毎月良くなる |
| IP展開 | ★★★ | 動画のキャラ一貫性は課題 |
| 技術実現性 | ★★★★★ | 最もシンプル。条件分岐+動画再生のみ |
| バイラル性 | ★★★★ | SNS投稿しやすい |
| **総合リスク** | **低** | 失敗しても被害が小さい |

### C: テキスト実況 + 静止画キャラ
| 観点 | 評価 | コメント |
|------|------|---------|
| 開発コスト | ★ | 最軽量。1週間 |
| エンタメ性 | ★★ | テキストの面白さに依存。実況力が必要 |
| IP展開 | ★★★ | 立ち絵があればIPになる |
| 技術実現性 | ★★★★★ | 技術的に最も簡単 |
| バイラル性 | ★★ | 地味。スクショ映えしない |
| **総合リスク** | **最低** | まずこれで「面白さ」を検証可能 |

### D: チャートオーバーレイ
| 観点 | 評価 | コメント |
|------|------|---------|
| 開発コスト | ★★ | チャートライブラリ+画像 |
| エンタメ性 | ★★ | ツール寄り。エンタメとしては弱い |
| IP展開 | ★ | キャラが小さい。IP展開しにくい |
| 技術実現性 | ★★★★ | 既存チャートライブラリを活用 |
| バイラル性 | ★★ | トレーダー層にはウケるかも |
| **総合リスク** | **低** | 差別化が弱いリスク |

### E: ショート動画/SNSコンテンツ自動生成
| 観点 | 評価 | コメント |
|------|------|---------|
| 開発コスト | ★★★ | 動画テンプレ+自動合成 |
| エンタメ性 | ★★★★ | ショート動画フォーマットの強み |
| IP展開 | ★★★★ | キャラがSNSで拡散される |
| 技術実現性 | ★★★ | FFmpeg + テンプレエンジン |
| バイラル性 | ★★★★★ | 最もバイラル向き |
| **総合リスク** | **中** | 「アプリ」ではなく「メディア」になる |

### F: ハイブリッド（C + B + E）
| 観点 | 評価 | コメント |
|------|------|---------|
| 開発コスト | ★★★ | 段階的に追加。初期はCのみ |
| エンタメ性 | ★★★★ | メリハリがある |
| IP展開 | ★★★★ | 複数チャネルでキャラ露出 |
| 技術実現性 | ★★★★ | 段階的に実装可能 |
| バイラル性 | ★★★★ | 日次ハイライト動画がバイラル向き |
| **総合リスク** | **低〜中** | 最も柔軟 |

## 検証プラン
1. **Week 1**: 過去1週間のBTC/USDTデータで2Bot（RSI vs MACD）の戦績を作成
2. **Week 1**: 戦績をスプレッドシートで見せて「面白い？」を聞く（仮説1検証）
3. **Week 2**: 方式B, C, Eのモックアップ/動画を作成
4. **Week 2**: SNSに投稿して反応を比較（仮説4検証）
5. **Week 3**: 最も反応が良かった方式をベースに決定

## 代替案
- 上記の全方式
- 「作らない」= 既存サービス（TradingView等）にキャラクターを追加するブラウザ拡張
- 「作らない」= Bot戦績データをAPIとして公開し、他の人が演出を作る
